Availability SLO
99.9 %
≤ 0.1 % error rate · ≤ 43.8 min downtime / month

Measured directly as (5XXError / Count) × 100 via CloudWatch Metric Math over a 5-minute rolling window. Triggers when the observed error rate exceeds 0.1 %, meaning the service is delivering fewer than 99.9 % successful responses. A zero-traffic guard (IF(m_count > 0, …, 0)) prevents false alarms during quiet periods.

Fix applied: replaced the composite "both error alarms firing" signal with a direct error-rate calculation. The previous design only triggered when both API Gateway AND Lambda error alarms were simultaneously active — it could not detect degradation when only one tier was failing or when error rates were high but below the per-alarm threshold.
Latency SLO
p95 < 500 ms
Tail latency objective for API responses

Measured directly from the Latency (p95) metric on the API Gateway, evaluated over 3 consecutive 1-minute periods. A composite alarm also captures average-latency degradation as an early-warning signal.

Fix applied: composite alarm logic changed from AND to OR. The prior AND condition required both p95 and average thresholds to breach simultaneously — masking scenarios where only one threshold was exceeded (e.g., tail latency spike without a corresponding average shift). Either condition alone is now sufficient to signal SLO risk.
